# DECISIONS
| Date | Commit | Decision | Rationale |
|------|--------|----------|-----------|
| 2026-08-21 | C08 | Manual WB disabled if COLOR_CORRECTION_MODE_TRANSFORM_MATRIX / AWB_OFF is unsupported | Hardware levels below FULL/LIMITED vary in manual WB support; per Law 1, MANUAL chip is absent if unsupported |
| 2026-08-23 | fix(C08) | Kelvin gains reproduce the selected illuminant's tint (3200K warm, 8000K cool) instead of compensating for it | C08 was committed with 4 failing ColorTemperatureTest cases; C08's prompt specifies "3200K warmer than 5600K" and a slider that visibly warms/cools, so the prompt and its tests win over the compensating-WB reading the code had implemented |
| 2026-08-23 | C09 | Zoom and torch are applied through CameraX CameraControl; only FPS and stabilization go through CaptureRequestOptions | CameraX owns zoom and torch state, so writing CONTROL_ZOOM_RATIO / FLASH_MODE through Camera2 interop would fight it. ControlApplier is still the single writer, so Law 4 holds |
| 2026-08-23 | C09 | STABILIZATION_MODE exposes only probed CONTROL_AVAILABLE_VIDEO_STABILIZATION_MODES and is absent when the device reports fewer than two | ControlId has one stabilization slot, and EIS and OIS are independent Camera2 keys; an OIS-only toggle would need its own control id, which C09 does not define. Devices with nothing to choose get no control per Law 1 |
| 2026-08-23 | C09 | Tap-to-focus moved from the PreviewView touch listener into the Compose gesture layer | The AndroidView consumed ACTION_DOWN, starving the parent pinch detector; one gesture owner keeps pinch and tap from competing for the same stream |
| 2026-08-23 | C09 | Device-auto FPS range snaps to the nearest probed option; ISO and shutter keep their 0 sentinels | An unsupported (15,30) default is meaningless, while ISO 0 / shutter 0 must keep meaning "let the device decide" rather than clamping to the range minimum |
| 2026-08-23 | C10 | Capture is JPEG-only and CAPTURE_FORMAT is absent, even where the probe reports RAW | CameraX 1.4.1 (the pinned stable version) has no DNG output path; C10 sanctions JPEG-only with the control absent rather than faking a RAW+JPEG option. Diagnostics still reports the hardware RAW capability |
| 2026-08-23 | C10 | FLASH_MODE added as its own ControlId, values mirroring CameraX ImageCapture (0 auto, 1 on, 2 off), defaulting to off | C10 requires flash-at-capture distinct from the C09 torch; routing it through the override system keeps one persistence and resolution path, and ControlApplier still owns the write |
| 2026-08-23 | C10 | ImageCapture uses CAPTURE_MODE_MINIMIZE_LATENCY | MAXIMIZE_QUALITY runs a pre-capture 3A routine that can disturb the manual exposure being previewed; C10 requires the still to match the preview's look |
| 2026-08-23 | C10 | Pre-Q writes go through MediaStore DATA plus WRITE_EXTERNAL_STORAGE (maxSdkVersion 28), requested once the camera is granted | minSdk is 26 but RELATIVE_PATH needs API 29; a denial surfaces as a capture error rather than blocking the viewfinder |
| 2026-08-23 | C11 | Sections are chip tabs rather than a swipe pager | C11 accepts "swipeable/tabbed"; tabs match the chip vocabulary the sheet already uses and keep one-handed reach without a pager's horizontal drag competing with the sliders inside each section |
| 2026-08-23 | C11 | A/B hold uses detectTapGestures onPress + tryAwaitRelease, not onLongPress | C11 demands instant response; a long-press callback would not fire until the ~500ms timeout, and release handling would still need the press path |
| 2026-08-23 | C11 | The reset glyph keeps its 48dp slot when hidden | Rows would otherwise shift sideways the moment a control is touched, moving the very target the finger is on |
| 2026-08-23 | C11 | A/B hold suspends overrides in the resolver rather than in the applier | Resolution is the single place effective values are decided (Law 2), so the readout chip and the preview change together with no second code path |
| 2026-08-23 | C12 | Presets express device-relative intent as out-of-range sentinels — ISO 1 for "base ISO", ISO 6400 for "as high as this sensor goes", 60fps for "fastest" | Law 5 clamping already adapts values per device, so the presets stay pure constants with no device branching, and the same constant means the right thing on every phone |
| 2026-08-23 | C12 | UV Hunt keeps AWB_MODE 0 even where manual WB is unsupported, letting it clamp to the nearest available mode | Dropping the entry would need device branching inside a constant; clamping resolves it to auto WB and COLOR_TEMP_K goes Absent on its own, which is the "where supported" behaviour C12 asks for |
| 2026-08-23 | C12 | Presets.byId falls back to DEVICE_AUTO for an unrecognised persisted id | A preset id removed in a later build must not strand the app on a preset it can no longer resolve |
| 2026-08-23 | C13 | User presets serialize as delimited text records (`id\|name\|description\|ID=T:raw;...`) in a DataStore string set, keyed by ControlId NAME not ordinal | No dependency and no reflection, and using enum names means reordering ControlId cannot silently rewrite a saved preset. Unknown ids and malformed entries are skipped so a record from a newer build still loads what this build understands |
| 2026-08-23 | C13 | Delete-fallback is expressed as lookup failure, not as a delete handler | Presets.byId already returns DEVICE_AUTO for an id nobody claims, so deleting the active preset needs no code path of its own and overrides are untouched — the resolver gains no special case (C13's explicit requirement) |
| 2026-08-23 | C13 | Preset names are sanitized (field delimiter stripped, 24 chars) rather than escaped | Escaping would complicate the format for a field the user retypes freely; sanitizing keeps records unambiguous and is verified by a round-trip test |
| 2026-08-23 | C13 | On a user chip, a long press ends the A/B audition and opens rename/delete | Both gestures live on the same chip: press engages the audition instantly, and crossing the long-press threshold releases it before the menu appears, so the two never render at once |
| 2026-08-23 | C13 | A snapshot stores every resolved control, including device-auto sentinels like ISO 0 | The snapshot is the collapsed effective state by definition; sentinels clamp harmlessly on load and are ignored by the applier in the mode that produced them |
| 2026-08-23 | C14 | MainActivity declares configChanges for orientation/screenSize instead of fading through black on rotation | C14 allows a ≤150ms black fade only if a re-layout flash is unavoidable; handling rotation in-process avoids the activity recreation that causes the flash at all, so no artificial fade was added. If a device still flashes, the fade remains the documented fallback |
| 2026-08-23 | C14 | decorFitsSystemWindows stays false in both modes, and no window insets are consumed | Content already extends behind the bars, so a transient bar swipe has nothing to re-inset and the layout cannot jump — which is C14's requirement 2 |
| 2026-08-23 | C14 | Double-tap-to-exit is registered only while edgeless | Adding onDoubleTap in normal mode would make every tap-to-focus wait out the double-tap timeout, a regression to C03's focus behaviour |
| 2026-08-23 | C14 | Edgeless lives in util/EdgelessController, restating the entire window state on every call | Idempotent application means a cold start into the persisted edgeless state runs the same code path as toggling into it, so there is no second way for the two to diverge |
| 2026-08-23 | C15 | Calibration is empirical and stored per device and per orientation, never derived from lens FOV metadata | The scale that sells the illusion depends on lens FOV, the user's arm length AND their eye-to-screen distance. Only the first is reported by the camera; the other two vary by person and by grip and are unknowable to the app. Portrait and landscape occlude different slices of the world, so one measured factor cannot serve both — the user's eye is the only instrument that can close the loop |
| 2026-08-23 | C15 | Zoom composition (userZoom × calibration) happens inside EffectiveSettings.resolve, and the UI reads userZoom back through a dedicated accessor | Composing in the resolver keeps C15's "not sprinkled through UI code" requirement literal. The accessor exists because the slider and pinch must edit the user's own zoom — reading the composed value back into the override would multiply calibration into itself on every drag |
| 2026-08-23 | C15 | TrueSight implies edgeless rather than being an independent flag | C15 defines TrueSight as edgeless plus calibration; deriving the window mode from either flag means the two can never disagree about whether chrome is hidden |
| 2026-08-23 | C15 | Cancelling a first-run calibration switches TrueSight back off | Leaving it on would strand the user in a see-through mode with no calibration, which is exactly the uncalibrated look C15 exists to fix. An orientation that already has a factor keeps it on cancel |
| 2026-08-23 | C15 | Brightness assist writes only the window's screenBrightness attribute and restores on dispose | The app must never touch system brightness settings; a window attribute is scoped to this app and is handed back automatically when TrueSight or the screen goes away |
